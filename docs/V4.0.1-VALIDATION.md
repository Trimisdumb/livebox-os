# V4.0.1 validation

Date: 2026-10-26. This patch preserves the V4 desktop and window system. It does not complete the remaining V4 roadmap or create a stable release automatically.

## Executed checks

- Backend: 99 tests passed on Windows, including per-account avatar isolation, UTF-8 names, replacement/deletion/persistence, image limits, CSRF, host fingerprints, reserved key names, SSH error classification and failed-test session rejection.
- Frontend: 11 tests passed. TypeScript/Vite production build passed. Hardware tests cover verified Livebox 4/5/6 mapping, the documented Livebox Fibre identifier, conflicts, unknown models and neutral fallback for Livebox 7/W7 without a verified photo.
- Dependency checks: pnpm audit and pip-audit reported no known vulnerabilities. Pillow 13.0.0 notices, including bundled codec notices, are retained.
- Real SSH: an isolated Debian 13/OpenSSH container with a disposable non-root account was used. The application registered it, generated its own dedicated key, displayed only the public part, accepted its host identity only after comparison with the trusted container console, and connected successfully. CPU delta sampling, RAM, filesystems, uptime and network byte counters were read from Linux. These are the container's kernel/filesystem views, not certification of a physical server or every distribution. Its missing systemd service listing returned unavailable.
- Native Windows reproduced the documented ssh-keyscan KEX problem. The new manual public-host-key path was used successfully without disabling StrictHostKeyChecking or changing cipher policy. Nonstandard SSH port handling was exercised.
- Avatar browser workflow: import, preview, zoom/position, save, reload, replacement, deletion and initial fallback were exercised. A two-color test image cropped to its right-hand blue region produced a blue 256 × 256 stored avatar, confirmed by decoding the saved file. Backend restart preserved the account name, registered server and dedicated key. Separate account sessions could not read each other's avatars.
- Scroll checks: Serveurs reached its maximum scroll offset, and Personnalisation with its full dock list reached its maximum offset. The desktop root did not scroll. The 320px profile dialog reached its bottom with no horizontal overflow; new touch controls measured 44px in layout. User-menu arrow keys/Home/Escape and return of focus were checked.

## Visual and image review

At 1920 × 1000, the desktop geometry matches V4: header 114px high, three-column grid x225/y430/width550, connection card x1302/y290/330 × 473.5, dock y915/height65 and avatar 32 × 32. Only the requested image/initial content changes. The supplied private wallpaper was not imported into the repository or used as a default.

All three bundled photos were opened and visually inspected. Their Commons descriptions identify the actual Livebox models and their authors grant CC BY-SA 4.0. Original bytes/checksums and visible credit links are retained; no AI image or unlicensed Orange promotional photo was added. LiveboxMonitor documents ProductClass naming. A connected Livebox reported the expected Livebox Fibre identifier during browser review. The native FastAPI static path was corrected and all three photos plus their credits were retrieved and compared byte-for-byte with the originals. No router setting changes were made for these checks.

The [profile screenshot](images/v4-profile.jpg) uses a disposable test account and a two-color crop fixture. Desktop screenshots use the built-in background and no connected personal equipment. No passwords, private keys, cookies, network inventory or private wallpaper are published.

The existing [GitHub Actions workflow](https://github.com/trim360/livebox-os/actions) additionally runs Windows/Linux backend tests, frontend checks, full-history secret scanning and isolated Docker Compose startup. Refer to that workflow for the actual result of the published commit. Source publication and secret checks run before pushing. The temporary SSH target and local preview are stopped after verification.
